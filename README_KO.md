# ScanBox PWA v1.1.3

아이폰에서 문서를 촬영하거나 이미지/PDF를 불러와 문서 보정, OCR, 검색 가능한 PDF, JPG/PNG 저장, PDF 편집 및 상호 변환을 수행하는 개인용 PWA입니다.

v1.1.3은 기존 ScanBox를 기반으로 문서 검출 정확도, 원근 보정 안정성, OCR 품질과 선택성, 다크 모드 UI를 개선한 버전입니다.

## v1.1.3 핵심 수정

- 자동 문서 보정이 첫 촬영에서 OpenCV 초기화를 실제로 기다리도록 수정했습니다. v1.1.2의 비동기 대기 누락으로 고성능 검출기 대신 JS fallback이 먼저 실행될 수 있던 문제를 바로잡았습니다.
- 문서 검출을 여러 Canny 조건, adaptive threshold, Otsu threshold, contour 후보 평가, Hough line fallback을 조합하는 방식으로 강화했습니다.
- 검출된 네 변 주변의 실제 밝기 경계를 다시 탐색하는 edge refinement와 아주 작은 안전 inset을 적용해 배경이 함께 잘리는 현상을 줄였습니다.
- OpenCV 원근 보정의 바깥 픽셀 처리 방식을 `BORDER_REPLICATE`에서 흰색 `BORDER_CONSTANT`로 바꾸고 JS fallback mesh도 세분화해 반복되는 평행사변형/타일 형태의 보정 흔적을 줄였습니다.
- 수동 4점 조정의 터치 범위를 키우고 드래그 중 확대경을 추가했습니다.
- OCR은 **기본 OFF**이며 마지막 ON/OFF 선택을 기기에 기억합니다. OFF 상태에서는 OCR 확인과 검색 가능한 PDF 선택이 비활성화됩니다.
- OCR 입력은 저장용 스캔 이미지와 분리하고 더 높은 OCR 해상도, 회색조/대비 정규화, Tesseract PSM 자동 모드와 저신뢰도 fallback 재시도를 적용했습니다.
- OCR 기반 파일명 자동 추천 기능을 삭제했습니다.
- 다크 모드에서 자동 문서 보정/OCR 토글의 ON 색상이 다른 CSS 규칙에 덮이던 문제를 수정했습니다.
- `보안 · 오프라인 준비` 상태와 실행 버튼을 하나의 컴팩트한 컨트롤로 통합했습니다.


## 1. 주요 기능

- 아이폰 카메라 촬영 / 사진 여러 장 불러오기
- 자동 문서 테두리 탐지와 원근 보정
- 수동 4점 문서 영역 보정 + 드래그 확대경
- 컬러 / 자동 / 그레이 / 문서 / 흑백 보정
- 페이지 회전 / 삭제 / 드래그 순서 변경
- 선택형 한국어 + 영어 OCR (기본 OFF, 마지막 선택 기억)
- 단어 좌표 기반 검색 가능한 PDF
- OCR 결과 확인과 복사
- 일반 PDF / 검색 PDF / JPG / PNG 저장
- PDF → JPG/PNG 변환
- JPG/PNG/WEBP/HEIC/HEIF → PDF 변환
- PDF를 편집기로 불러와 재정렬·회전·삭제·OCR 후 저장
- 용량 절약 / 표준 / 고화질 / 원본에 가깝게 화질 설정
- 오프라인 준비

요청에 따라 임시 작업 자동 저장은 포함하지 않았습니다. 앱을 닫거나 새로고침하기 전에 결과 파일을 저장해 주세요.

## 2. v1.1.3 보안 구조

### 문서 데이터
사용자가 선택한 사진, PDF 및 OCR 결과를 외부 서버로 업로드하는 코드는 없습니다. 처리는 브라우저 메모리에서 수행합니다. 인터넷 연결은 고정 버전 OpenCV/Tesseract/PDF.js 실행 자산을 jsDelivr에서 내려받는 용도로만 허용됩니다.

### 실행 엔진
JSZip은 프로젝트에 로컬로 포함됩니다. PDF 생성은 ScanBox 자체 경량 PDF 엔진을 사용하므로 외부 PDF 생성 라이브러리나 한글 폰트를 내려받지 않습니다.

OpenCV.js, Tesseract.js/코어/언어모델, PDF.js는 용량이 큰 실행 자산이므로 **처음 필요한 시점** 또는 `보안 · 오프라인 준비`를 실행할 때 아래 방식으로 준비합니다.

1. 정확히 고정된 버전 URL에서 HTTPS로 다운로드
2. 허용된 호스트인지 검사
3. redirect 최종 목적지도 다시 검사
4. 브라우저에서 SHA-256 계산
5. 최초 SHA-256을 앱 버전별로 잠금
6. 앱 전용 Cache Storage에 같은 출처의 가상 경로로 저장
7. 이후 실행은 캐시 사본에서 수행
8. 같은 버전 URL의 내용이 잠긴 SHA-256과 달라지면 실행 중단

이 방식은 CDN 스크립트를 HTML에서 곧바로 실행하는 방식보다 공급망 노출을 줄입니다.

**한계:** 최초 다운로드 시점 자체가 이미 변조된 경우를 사전에 알 수 있는 사전 등록 해시(pre-known hash)는 포함하지 않습니다. 따라서 최초 준비 시 고정 버전 배포 경로(jsDelivr)를 신뢰하는 TOFU(Trust On First Use) 방식입니다. 민감도가 매우 높은 조직 문서에는 조직이 직접 검증한 엔진 파일을 동일 출처에 자체 호스팅하는 방식이 더 강합니다.

### CSP
앱은 Content Security Policy를 사용하여 실행/네트워크 범위를 제한합니다. 기본적으로 자체 출처만 실행하며, 최초 엔진 준비용 연결은 jsDelivr로 제한됩니다. object/frame/form 기능은 차단합니다.

### PDF 입력
PDF.js는 PDF를 편집/이미지 변환하기 위한 렌더러로만 사용하며 `isEvalSupported: false`, `useWasm: false`, 자동 스트리밍/자동 가져오기 제한 등을 적용합니다. ScanBox는 PDF 뷰어 UI의 JavaScript action을 실행하지 않습니다.

### 파일 보호 한도
아이폰 Safari의 메모리 폭주와 비정상 파일 입력을 줄이기 위해 다음 제한이 있습니다.

- 이미지 1개: 최대 40 MB
- 한 번에 선택한 이미지: 최대 200 MB
- PDF: 최대 120 MB
- PDF 분석 / 개별 페이지 렌더링: 각 30초를 넘으면 중단
- 한 작업: 최대 100 페이지
- PDF ↔ 다중 이미지 ZIP: 최대 60 페이지
- 캔버스: 약 2,000만 픽셀 상한
- JPEG/PNG/WEBP 입력: 최대 한 변 12,000 px / 약 5,000만 픽셀을 헤더에서 사전 검사
- HEIC/HEIF: 파일 크기 및 실제 디코딩 단계의 캔버스 상한 적용
- SVG 입력: 보안상 차단


## 기존 v1.1.2에서 v1.1.3으로 업데이트

이미 GitHub Pages에 v1.1.2를 올려둔 경우 새 저장소를 만들 필요가 없습니다.

1. v1.1.3 ZIP을 압축 해제합니다.
2. 기존 `scanbox-pwa` 저장소에서 `Add file` → `Upload files`를 엽니다.
3. 압축 해제한 폴더 **안의 파일과 폴더 전체**를 업로드하여 동일한 경로의 파일을 v1.1.3 내용으로 갱신합니다. 기존 파일을 모두 덮어써야 `app.js`, `styles.css`, `sw.js`, `secure-runtime.js`의 버전이 함께 맞습니다.
4. `Commit changes`를 누릅니다.
5. GitHub Pages 배포가 끝난 뒤 iPhone Safari에서 Pages 주소를 한 번 직접 엽니다.
6. 화면 상단이 `ScanBox 1.1.3`인지 확인한 뒤 홈 화면의 ScanBox를 완전히 종료하고 다시 실행합니다.
7. 설정 → `보안 · 오프라인 준비` → `준비`를 다시 실행합니다. 버전별 캐시가 분리되어 있으므로 v1.1.3에서 한 번 다시 준비하는 것이 정상입니다.
8. 완료되면 설정 첫 항목의 한 줄 컨트롤에 **`완료 ✓ · 다시 확인`**이 표시됩니다.

계속 이전 화면이 나오면 Safari에서 Pages 주소를 새로고침한 뒤 홈 화면 앱을 다시 실행하세요. 그래도 갱신되지 않으면 홈 화면의 ScanBox 아이콘만 삭제하고 Pages 주소에서 다시 `홈 화면에 추가`하면 됩니다. GitHub 저장소와 문서 파일은 삭제되지 않습니다.

## 3. 처음 설치하는 방법

### 준비물
- Windows PC 또는 Mac 중 하나
- GitHub 계정
- iPhone
- 최초 설치/보안 준비 시 인터넷 연결

Mac, Xcode, Apple Developer 계정, App Store 등록은 필요하지 않습니다.

### 1) ZIP 압축 풀기
`ScanBox-PWA-v1.1.3.zip`을 PC에 다운로드하고 압축을 풉니다.

저장소 최상단에 아래 파일들이 위치해야 합니다.

```text
index.html
theme-init.js
app.js
styles.css
sw.js
secure-runtime.js
pdf-engine.js
manifest.webmanifest
.nojekyll
README_KO.md
SECURITY.md
THIRD_PARTY.md
QA_REPORT.md
SHA256SUMS.txt
icons/
vendor/
```

### 2) GitHub 저장소 만들기
1. GitHub 로그인
2. 오른쪽 위 `+`
3. `New repository`
4. Repository name: `scanbox-pwa` 권장
5. GitHub Free이면 `Public`
6. `Create repository`

`Public`은 앱 소스가 공개된다는 의미입니다. ScanBox로 촬영한 개인 문서가 GitHub 저장소에 업로드된다는 의미는 아닙니다.

### 3) 파일 올리기
1. 새 저장소에서 `Add file`
2. `Upload files`
3. 압축 해제한 **폴더 자체가 아니라 폴더 안의 모든 파일과 폴더**를 드래그
4. 저장소 첫 화면에 `index.html`이 바로 보이는지 확인
5. `Commit changes`

정상:
```text
scanbox-pwa/
  index.html
  app.js
  ...
```

잘못된 예:
```text
scanbox-pwa/
  ScanBox-PWA-v1.1.3/
    index.html
```

### 4) GitHub Pages 켜기
1. 저장소 `Settings`
2. 왼쪽 `Pages`
3. `Build and deployment`
4. Source → `Deploy from a branch`
5. Branch → `main`
6. Folder → `/(root)`
7. `Save`

생성 주소는 보통 다음 형태입니다.

```text
https://사용자아이디.github.io/scanbox-pwa/
```

### 5) iPhone에 설치
1. 반드시 iPhone Safari에서 위 주소 열기
2. Safari 공유 버튼
3. `홈 화면에 추가`
4. `웹 앱으로 열기` 옵션이 보이면 켜기
5. `추가`

홈 화면에 ScanBox 아이콘이 생깁니다.

### 6) 첫 실행 후 보안 · 오프라인 준비
1. 홈 화면 ScanBox 실행
2. `설정`
3. `보안 · 오프라인 준비` → `준비`
4. 100%가 될 때까지 앱을 닫지 않기

이 과정에서 문서보정, OCR, PDF 읽기 엔진과 한국어/영어 OCR 모델을 버전 고정 URL에서 받아 최초 SHA-256 지문을 생성해 잠근 후 앱 캐시에 저장합니다. 이 지문은 사전 등록된 공식 해시가 아니라 첫 정상 사용을 기준으로 고정하는 TOFU 방식입니다.

처음에는 인터넷이 필요합니다. 준비가 끝난 뒤 캐시가 유지되는 동안 주요 기능은 오프라인에서도 사용할 수 있습니다. iOS가 웹사이트 데이터를 정리하면 다시 준비해야 할 수 있습니다.

## 4. 기본 사용법

### 문서 촬영
`스캔 → 문서 촬영`을 누릅니다. 자동 문서 보정이 켜져 있으면 문서 사각형을 찾아 원근을 보정합니다. 자동 검출이 실패해도 원본 사진으로 계속 작업할 수 있습니다.

### 네 모서리 직접 수정
페이지의 `영역 조정`을 눌러 네 점을 문서의 실제 모서리로 움직인 뒤 `보정 적용`을 누릅니다.

### 페이지 정렬
각 페이지의 `≡` 손잡이를 누른 채 위아래로 드래그합니다.

### 보정 모드
- 컬러: 원본 색상 유지
- 자동: 밝기·대비를 약하게 자동 보정
- 그레이: 회색조 문서
- 문서: adaptive threshold로 그림자/조명 편차 대응
- 흑백: 강한 텍스트 흑백 분리

### 검색 가능한 PDF
`검색 가능한 PDF`를 선택하면 OCR 단어별 위치 정보를 사용해 스캔 이미지 위에 보이지 않는 텍스트 레이어를 배치합니다. 검색, 복사, 텍스트 추출이 가능한 PDF를 목표로 합니다. OCR은 100% 정확하지 않습니다.

### PDF 편집
`PDF 편집`으로 PDF를 불러오면 각 페이지를 이미지로 안전 렌더링해 일반 스캔 페이지처럼 정리합니다. 기존 PDF의 벡터 텍스트, 링크, 디지털 서명, 폼, 주석 등은 보존되지 않습니다.

## 5. 권장 화질

일반 문서는 `표준`을 권장합니다.

- 용량 절약: 최대 긴 변 약 2,000 px
- 표준: 약 3,000 px
- 고화질: 약 4,500 px
- 원본에 가깝게: 최대 약 5,500 px, 단 픽셀 상한 적용

작은 글씨가 많은 문서만 고화질을 사용하면 처리 속도와 메모리 사용을 줄일 수 있습니다.

## 6. 개인정보와 GitHub Pages

GitHub Pages에는 앱 코드가 올라갑니다. ScanBox에서 선택하거나 촬영한 문서는 브라우저 내부의 Blob/Canvas 메모리로 처리하며 저장소에 자동 업로드하지 않습니다.

다만 PWA 자체가 GitHub Pages에서 제공되므로 GitHub 계정 탈취 또는 저장소의 앱 코드가 변조될 경우 다음 접속에서 변조된 앱이 배포될 수 있습니다. GitHub 계정에는 2단계 인증(2FA)을 켜는 것을 강하게 권장합니다.

## 7. 배포 파일 무결성 확인

프로젝트 루트의 `SHA256SUMS.txt`에는 배포 ZIP에 포함된 주요 파일의 SHA-256이 기록되어 있습니다. GitHub 업로드 전후 파일이 의도치 않게 바뀌었는지 감사할 때 사용할 수 있습니다. 이 목록은 **프로젝트 파일 자체의 변경 확인용**이며, 최초 CDN 엔진의 진위를 독립적으로 증명하는 서명은 아닙니다.

## 8. 문제가 생기면

- 이전 화면이 계속 보임: Safari에서 Pages 주소를 직접 열고 새로고침 → 홈 화면 앱 완전 종료 후 재실행
- 엔진 준비 실패: 인터넷 연결 확인 후 `설정 → 보안 · 오프라인 준비` 재실행
- SHA-256 불일치: 실행을 중단하도록 설계되어 있습니다. 임의로 우회하지 말고 앱 버전과 배포 파일을 먼저 확인하세요.
- HEIC 열기 실패: iOS/WebKit 버전에 따라 디코딩이 제한될 수 있습니다. 사진 앱에서 JPG로 공유/변환 후 다시 시도하세요.
- 큰 PDF 종료: PDF를 분할하거나 페이지 수를 줄인 뒤 처리하세요.

자세한 보안 설계와 한계는 `SECURITY.md`를 참고하세요.
